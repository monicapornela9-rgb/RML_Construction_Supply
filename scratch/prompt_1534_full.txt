# 5. STRICT PASSWORD POLICY AND VALIDATION

Implement a strict password policy for all newly registered customer accounts.

### Required password conditions:

Every password must:

1. Contain at least 8 characters.
2. Include at least one uppercase letter (A–Z).
3. Include at least one lowercase letter (a–z).
4. Include at least one number (0–9).
5. Include at least one special character (such as @, #, $, !, %, or &).
6. Not contain spaces.
7. Not be a commonly used or easily guessed password.

### Password Validation UI

Display the password requirements directly below the password input field.

Implement:

- Real-time password validation.
- Password strength indicator: Weak, Medium, or Strong.
- A checkmark beside every requirement once satisfied.
- Show/Hide Password functionality.
- Confirm Password field.
- Clear error messages when requirements are not met.
- Prevent account submission until all password requirements are satisfied.

The password strength indicator should update automatically as the customer types.

### Password Security

- Validate passwords on both the frontend and backend.
- Never store passwords in plain text.
- Use a secure password hashing algorithm such as Argon2id or bcrypt with appropriate settings.
- Never expose passwords in application logs or error messages.
- Prevent commonly used and compromised passwords where practical.
- Apply secure password handling to password changes and resets.
- Do not unnecessarily modify existing Admin/Staff and Driver passwords.
- Do not force existing accounts to reset their passwords unless required by an approved migration.
